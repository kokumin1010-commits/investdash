# InvestDash 重复观察标的导航设计

**作者：Manus AI**  
**适用页面：** `client/src/pages/Watchlist.tsx`  
**适用接口：** `portfolio.lookup`、`watchlist.add`

## 目标

当前新增观察标的流程会先通过 `portfolio.lookup` 获取真实行情预览，但只有在提交 `watchlist.add` 后才发现重复，并以 `CONFLICT` 错误结束。新的流程将重复状态提前到预览阶段：如果标的已经在观察列表中，用户可以直接关闭对话框并滚动到对应观察卡；如果已经持有，用户可以直接进入 `/holdings/:id`；如果两种状态同时存在，则同时显示两个入口，并以保有详情作为主操作。

| 状态       | 对话框提示               | 主操作                 | 次操作                 |
| ---------- | ------------------------ | ---------------------- | ---------------------- |
| 未登记     | 继续说明 AI 草稿流程     | `この銘柄を追加`       | 无                     |
| 仅观察     | `ウォッチリスト登録済み` | `登録済みの銘柄を見る` | 无                     |
| 仅持有     | `保有銘柄として登録済み` | `保有詳細を見る`       | 无                     |
| 观察且持有 | 同时明确显示两种状态     | `保有詳細を見る`       | `ウォッチカードを見る` |

## 接口契约

`portfolio.lookup` 已是受保护过程，因此可安全加入当前用户的登记状态。响应在现有行情、企业资料字段之外，新增 `existingWatch` 与 `existingHoldings`。`existingWatch` 至少返回 `id`、`symbol`、`name`；`existingHoldings` 返回全部同 symbol 持仓的 `id`、`broker`、`name`，按持仓 ID 升序，以第一条作为默认详情入口。多账户持仓在 UI 中显示 `N口座で保有`，但不隐藏其他账户的存在。

`watchlist.add` 继续保留数据库查询和 `CONFLICT`，用于防止用户预览后另一请求抢先写入的竞态；重复错误不再作为正常 UI 控制流。

## 导航与高亮

观察卡根节点使用稳定锚点 `id="watch-{id}"`。点击观察入口时，对话框关闭，页面 URL 写入 `?focus={id}`，目标卡执行 `scrollIntoView({ behavior: "smooth", block: "center" })`，并出现短暂的蓝色 ring/background 高亮。URL 中的 focus 可直接打开和复制；浏览器前进/后退触发 `popstate` 后重新解析 focus。若 ID 不存在，页面不报错且不滚动。

高亮只改变视觉强调，不改变观察数据、排序、AI 提案状态或目标价。动画遵守 reduced-motion：滚动改为 `auto`，卡片仍保留静态 ring，确保不依赖动画传达定位结果。

## 验收范围

必须覆盖未登记、仅观察、仅持有、观察且持有四个分支；同时保留服务器 add 的重复冲突测试。桌面与 390px 生产验收需要确认：对话框关闭、目标卡进入视区、目标卡可识别地高亮、持仓入口进入正确 `/holdings/:id`，且没有横向溢出或真实用户数据写入。
