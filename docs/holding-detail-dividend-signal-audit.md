## 结论

保有详情已经从 `portfolio.detail` 取得账户级真实股息视图，但 UI 没有显示。`view.dividend` 已包含直近 12 个月每股配当、账户级年間受取额、日元换算、现价利回り、取得价利回り、支払次数、特别配当、持续配当估计、最后配当日和更新时间。因此新增显示无需数据库迁移或再次抓取，只需保持 `null=未取得`、`0=无配` 的现有语义。[1]

AI 主判断的根因不是模型误解，也不是缺少持仓数据。`SignalContext` 已传入 symbol 合计株数、加权取得价、损益率、组合构成比与多账户内译；但系统 prompt 明确要求 rationale **必须以“今この株を1株も持っていなかったら買うか”开头**。所以实际持仓信息虽然存在，却被强制降为后文材料。[1]

## 真实样本

HMY（楽天証券 iSPEED）当前持有 54 株、现价 $20.23、symbol 构成比 0.0201%。直近 12 个月每股配当 $0.312、账户级年間配当 $16.848 / ¥2,696.32、现价利回り 1.5423%，数据更新时间为 2026-08-29 04:22 JST。现有 rationale 还错误写成“无配当”，与数据库真实股息冲突，因此新 prompt 必须把股息数据直接放入上下文并禁止忽略。[1]

## 设计约束

详情页主判断必须先回答“当前持有的这笔/这个 symbol 现在怎样处理”，并明确区分 `ADD / HOLD / WATCH / REDUCE / EXIT`。取得价与损益可用于税务、风险和执行说明，但不得仅因浮盈浮亏决定公司价值。未持有假设仍可保留为第二层参考，用于检验沉没成本偏差，但不得再出现在主文首句或标题旁主徽章。

行动数量采用确定性计算，不让模型自由编造。ADD 复用组合级价格带 sizing；HOLD/WATCH 为零交易；REDUCE 默认按 symbol 合计数量的 25%（若构成比超过 5%，至少降至 5%），按市场交易单位向下取整；EXIT 为全部退出。多账户时显示 symbol 合计并提示用户确认由哪个账户执行，系统不擅自分配账户。

“予想配当利回り”使用 `recurringYieldPct`，并明确标注“直近12か月実績ベース”，避免把历史支付冒充公司指引。年間配当見込额同样优先采用特别配当剔除后的持续水准；若无特别配当，则与直近 12 个月实绩一致。所有金额为税前。

## 最终信息架构

顶部持仓指标卡在现有保有株数、取得单价、现价、评价额、损益、52周区间、持有期间之外，增加一个独立的**予想配当**区域。桌面显示 `予想配当利回り / 年間配当見込 / 1株配当`，390px 维持两列流式布局。利回り采用持续配当每股额 ÷ 当前价，年間配当采用持续配当每股额 × 当前账户株数，再按现有 FX 转为日元。辅助文案显示“直近12か月実績ベース・税引前”和数据更新时间；特别配当存在时明确标注已剔除。`null` 显示“未取得”，`0` 显示“無配”，不得混为一谈。

AI 卡片的标题下第一层改为**現在の保有への提案**。主文必须从当前行动开始，例如“2,000株を保有中。500株の一部売却を検討し、実行後は1,500株・構成比0.47%”或“現在の54株を維持し、追加売買は行わない”。主文不再以未持有假设开头。

执行量由服务器确定性派生，而不是让模型编造：ADD 使用当前价格带的组合级 sizing；HOLD/WATCH 为 0 株；REDUCE 默认 25%，但构成比超过 5% 时至少降至 5%；EXIT 为全部。日本股按 100 株、美国/新加坡股按 1 株、香港股按现有最小单位规则向下取整。多账户时以 symbol 合计计算，并显示“执行账户由用户确认”。

“未保有なら買うか”和“株価と中身の伸び”保留在**参考視点**折叠区，默认关闭；HoldingDetail 顶部移除未持有徽章。旧 v2 信号继续可读，但 schemaVersion 升级后统一判为 stale 并进入再分析队列；生产 112 个 symbol 按现有配额保护批量刷新。
