# InvestDash 新环境恢复报告

**作者：Manus AI**  
**日期：2026-08-25**

## 恢复结论

InvestDash 已从 GitHub 仓库重建到一个独立的新全栈项目。新项目沿用原有业务模型和 25 个 Drizzle 迁移，恢复了个人パスコード访问、投资组合仪表盘、持仓、资产内訳、ウォッチリスト、卖买/月次记录、行情更新、企业基础资料、新闻抓取以及分析服务接口。界面品牌统一为 **InvestDash / PRIVATE PORTFOLIO OS**，并针对 390 px 手机视口重新完成卡片、筛选和导航验收。

旧网址仍属于平台数据迁移后的待恢复项目；在没有 `.manustask` 备份的情况下，旧数据库和运行历史不能由源码直接取回。官方恢复说明同样要求使用原始备份包执行恢复，因此本次采用“新项目 + GitHub 可重建数据”的方式，而不是继续修改旧网址。[1]

## 无法从仓库恢复的数据

| 数据缺口 | 原因与处理 |
|---|---|
| 2026-07 及更早月次明细 | 仓库没有逐标的数量、成本和价格；未创建估算数据 |
| 旧新闻与 AI 分析历史 | 仅存在于旧数据库运行记录；新环境从真实来源重新积累 |
| 投资咨询对话与信号历史 | 未写入 GitHub；保留空状态，不制造历史 |
| 导入图片与旧上传文件 | 旧对象存储内容不在源码仓库 |
| 部分价格带与运行配置 | 只恢复仓库中有明确数据来源的内容 |

> 本次恢复遵循“可验证才恢复”的原则。对没有原始明细的数据，不使用估算值填充，以避免将推测误认为真实投资记录。

## 定时任务方案

新项目已准备 33 个生产回调任务。日本市场收盘后行情更新安排在平日 JST 15:30，美国市场收盘后更新安排在平日 JST 06:30。每日新闻从 JST 07:00 开始，123 个去重标的按每批四个、每三分钟一批拆分为 31 个回调，最后一批在 JST 08:30 执行。

| 工作内容 | 日本时间 | UTC cron | 数量 |
|---|---:|---|---:|
| 日本收盘后行情 | 平日 15:30 | `0 30 6 * * 1-5` | 1 |
| 美国收盘后行情 | 平日 06:30 | `0 30 21 * * 1-5` | 1 |
| 每日新闻抓取与分析 | 每日 07:00–08:30 | 从 `0 0 22 * * *` 起每三分钟一批 | 31 |

实际注册必须在新项目发布后进行，因为平台的定时服务只能调用生产网址。注册脚本位于 `scripts/register-heartbeats.sh`，完整运维说明位于 `docs/scheduled-jobs.md`。

## 当前限制与后续动作

模型目录仍可发现 Gemini、GPT 和 Claude 模型，但当前项目的最小模型调用返回外部服务用量限制。因此分析接口和失败处理均已恢复，实际 AI 输出需要等待该外部服务恢复。新闻正文不会丢失，界面会显示“未分析”，后续任务将重新处理这些记录。

新项目发布后，应立即执行三项生产验收：确认新网址首页和パスコード流程，确认 tRPC 行情查询，确认 `/api/scheduled/*` 回调在 cron 身份下返回成功。随后注册并手动运行定时任务，保存新 `task_uid` 和首次运行日志。
