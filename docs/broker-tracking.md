# 証券プラットフォーム（口座）別の管理

ユーザー要望「どの銘柄がどのプラットフォームか、ぱっと見て分かるように」に対する実装記録。

## データ設計

`holdings` テーブルに `broker` 列を追加（enum, デフォルト `other`）。

| 値 | 表示名 | 短縮名 | 色 |
|---|---|---|---|
| `moomoo_jp` | moomoo 日本版 | moomoo | オレンジ `#f97316` |
| `rakuten_ispeed` | 楽天証券 iSPEED | 楽天 | 赤 `#dc2626` |
| `futu` | 富途牛牛 / Futu | 富途 | 青 `#2563eb` |
| `other` | その他 | その他 | グレー `#94a3b8` |

既存の 27 銘柄はすべて moomoo 日本版から取り込んだものなので、`UPDATE holdings SET broker = 'moomoo_jp'` で移行済み。

配色は各社のブランドカラーに寄せている。moomoo のロゴがオレンジ、楽天が赤、富途が青であるため、
アプリを普段使っているユーザーが色を見た瞬間にどの口座か判別できる。

## 表示箇所

| 画面 | 表示形式 |
|---|---|
| 保有一覧（スマホ） | 銘柄カード右上にシグナルバッジの下に短縮バッジ（moomoo） |
| 保有一覧（デスクトップ） | 「口座」列を銘柄名の右に追加、正式名バッジ |
| 銘柄詳細 | ヘッダーの市場バッジの隣 |
| ダッシュボード | 「証券口座別」カード。評価額・含み損益・構成比・銘柄数を口座単位で集計 |

口座別集計は `buildPortfolio()` の戻り値に `brokers: BrokerSlice[]` として追加。
セクター別集計と同じループ内で計算するため追加のクエリコストはない。
`BrokerSlice` はセクターと違い `pnl` / `pnlPct` を持ち、口座ごとの成績を比較できる。

## 入力経路

1. **スクショ取込** — 取込ページで選んだ証券アプリ（`formatId`）を `brokerFromFormatId()` で
   `broker` に変換して保存。既存銘柄の更新時も上書きする（口座を移した場合に追従するため）
2. **手動追加** — 追加ダイアログに「保有している証券口座」の選択を追加。既定は moomoo 日本版
3. **編集** — 編集ダイアログでも変更可能

## 絞り込み

保有一覧に口座フィルタを追加。ただし **2 口座以上に銘柄がある場合のみ表示** する。
現状は moomoo のみなので UI に出ない。不要な選択肢で画面を煩雑にしないための判断。

## 今後の拡張

同一銘柄を複数口座で保有するケースには現状未対応（`holdings` は symbol でユニーク）。
必要になった時点で `(symbol, broker)` の複合キーに変更し、集計側で名寄せする方針。
