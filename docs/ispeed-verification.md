# 楽天証券 iSPEED のフォーマット検証記録

検証日: 2026-08-16 / モデル: `gemini-3.1-pro-preview` / 定義: `server/services/brokerFormats.ts`

## moomoo との違い

同じ日本株の保有一覧でも構造がかなり違うため、専用のレイアウト定義が必要だった。

| 観点 | moomoo 日本版 | 楽天証券 iSPEED |
|---|---|---|
| 1 銘柄の行数 | 2 行 | 2 行（同じ） |
| 列の内容 | 固定（評価額・損益・現在値/取得単価） | **横スクロールで 3 種類に変化** |
| 純資産・預り金 | 画面上部に表示 | **表示されない** |
| 銘柄名 | ほぼ省略されない | **頻繁に「…」で省略** |
| 損益の色 | 緑がマイナス | **赤がプラス・緑がマイナス** |
| 特有の要素 | 口座区分タグ（一般/NISA/特定） | 「貸株中」バッジ、「（執行中）」列 |

## 3 つのビュー

iSPEED は列見出しの「‹ ›」で横スクロールでき、見えている列が変わる。
同じ保有銘柄でも 3 通りの画面になるため、それぞれの扱いを定義した。

| ビュー | 表示内容 | 取り込み方針 |
|---|---|---|
| A 取得単価 | 保有数量 / （執行中）/ 平均取得価額 / 現在値 | **これだけ取り込む** |
| B 評価額 | 時価評価額 / 評価損益額 / 評価損益率 | 数量・取得単価を null にし、評価額と損益のみ埋める |
| C 指標 | PER / PBR / 配当利回り | **取り込まない**（空配列 + 案内文を返す） |

### なぜ A だけで足りるのか

評価額は `保有数量 × 現在値`、評価損益は `評価額 −（保有数量 × 平均取得価額）` で導ける。
B の画面と突き合わせて検算した結果、計算値が完全に一致した。

| 銘柄 | A から計算した評価額 | B の表示 |
|---|---|---|
| ヤクルト | 1,800 × 2,881.5 = 5,186,700 | 5,186,700 |
| SUMCO | 1,100 × 3,920 = 4,312,000 | 4,312,000 |
| 住友化学 | 10,000 × 530.5 = 5,305,000 | 5,305,000 |
| 産業ファンド投資法人 | 3 × 136,900 = 410,700 | 410,700 |

計算した方が OCR の読み取り誤差が入らないため、むしろ精度が高い。

### なぜ C を取り込まないのか

PER・PBR・配当利回りは株価データ API から取得できる。加えて **iSPEED の表示自体に問題がある**。

| 銘柄 | iSPEED の PER 表示 | 実態 |
|---|---|---|
| SUMCO | 0.00 | 赤字のため算出不能 |
| Kudan | 0.00 | 同じく赤字 |
| 産業ファンド投資法人 | 0.00 | REIT のため概念が異なる |

`0.00` をそのまま取り込むと「PER 0 倍の超割安株」と誤認識し、シグナル判定を歪める。
API 経由なら「データなし（null）」として正しく扱える。

## 検証結果

### ビュー A（IMG_7614）— 本命

11 銘柄すべて正しく抽出。**整合性チェック 22 項目すべて誤差 0.00%**。所要 37.9 秒。

特に難しい点をすべてクリアした。

| 課題 | 結果 |
|---|---|
| 「（執行中）」の 0 を保有数量と誤認しないか | 全銘柄で正しく上段の数量を採用 |
| 省略名の補完 | 産業ファ…→産業ファンド投資法人、オリエンタ…→オリエンタルランド、LINE…→LINEヤフー、サイバーエ…→サイバーエージェント、東映アニ…→東映アニメーション（5 件すべて正解） |
| REIT の投資口（数量 3） | 3 口として正しく処理 |
| 「貸株中」バッジの除外 | 銘柄名・コードに混入なし |
| 含み損の符号 | オリエンタルランド −105,340 / 東映アニメーション −141,434 を負値で出力 |
| 純資産・預り金 | 画面に無いため null（推測で埋めなかった） |

### ビュー B（IMG_7615）

11 銘柄の評価額・評価損益を抽出し、**数量・取得単価・現在値は正しく null**。
推測で埋めることをしなかった。画面下端でナビゲーションバーに隠れていた
ポーラ・オルビスホールディングス以降を自主的に除外し、警告に明記した。

### ビュー C（IMG_7616）

意図どおり `holdings: []` を返し、「指標ビューのため保有数量・取得単価が読み取れない。
取得単価が見える画面を送ってほしい」と案内した。所要 9.7 秒。

## 運用上の指針

iSPEED の銘柄を追加する際は、**ビュー A（平均取得価額が見えている画面）だけ**送れば足りる。
ビュー B・C は不要。
