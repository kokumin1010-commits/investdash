# 既存保有・買い増し候補の統合設計

## 目的

Dashboard の `AI 保有シグナル` に `ADD 0` と表示されていても、それだけで「買い増し候補がない」とは判断できない。InvestDash には、保有状態の分析、価格帯、ポートフォリオ制約、保存済み AI 文面という異なる時点・目的の判断層があるためである。本対応では各層を混同せず、既存保有銘柄について**現在の実データから決定論的に再計算できる、確認専用の買い増し検討順**を Dashboard と Buy Plans の上部へ表示する。

## 判断層

| 判断層 | 役割 | 表示上の扱い |
|---|---|---|
| AI 保有シグナル | 現在の実保有に対する `ADD / HOLD / WATCH / REDUCE / EXIT` | `AI 保有シグナル内訳` として維持する。`ADD 0` はこの層だけの件数である |
| 価格帯 | 現在値が `ADD_MAIN / ADD_SMALL / HOLD / VERIFY` のどこにあるか | 価格帯内件数として表示するが、注文候補とは扱わない |
| 安全ゲート | 数量、単一銘柄比率、業種集中、現金性資産、IBKR リスク、未照合項目、シグナル競合 | 通過件数を中間段階として表示する |
| 厳格確認済み候補 | 安全ゲートに加えて、最新シグナル、材料品質、現在値の価値確認、投資カード確信度、確認済み懸念を確認 | `今月の買い増し検討順` として順位・株数・金額・実行後構成比を表示する。注文ではない |
| 保存済み AI 補足見解 | 手動実行時点の `BUY / WAIT / SKIP` 文面 | ライブ候補数の判定元にしない。保存日と7日超の古さを明示する |

## 厳格確認済み候補の条件

対象は全口座合算で現在保有中かつ、現在価格が `ADD_MAIN` または `ADD_SMALL` の価格帯にある銘柄だけである。そのうえで、以下をすべて満たすものだけを候補にする。

1. 既存ランキングの安全ゲートを通過し、実行可能な金額と株数が算出されている。
2. 買付後の単一銘柄比率が 5% 以下で、業種上限を超えない。
3. IBKR リスクが `WARNING / DANGER` ではない。
4. 未照合の確認項目がない。
5. 保有シグナルが `ADD` または `HOLD` であり、`WATCH / REDUCE / EXIT` と競合しない。
6. 保有シグナルが再分析待ちではなく、材料品質が `STRONG` または `MODERATE` である。
7. 現在値と企業価値の補助確認 `wouldBuyNow` が `YES` である。この値だけで売買判断は行わない。
8. 確認済み懸念が 0 件である。
9. 投資カード確信度が 3/5 以上である。

条件を満たさない銘柄は削除せず、価格帯一覧と全プラン一覧に残す。厳格候補から外れた理由は `SAFETY_GATE`、`CONFIRMED_CONCERN`、`SIGNAL_CONFLICT`、`SIGNAL_STALE_OR_MISSING`、`SIGNAL_DATA_LIMITED`、`VALUATION_NOT_POSITIVE`、`LOW_CONVICTION` として集計できる。

## 表示と行動の意味

候補カードには、厳格候補内の順位、元の価格帯順位、現在値、現在保有株数、買い増し目安株数・金額、実行後株数、実行後構成比、価格帯理由、AI 保有シグナル、投資カード確信度を表示する。

> この順位と数量は、月1回程度の確認を支援する参考案であり、発注指示ではない。実行前に決算、ニュース、口座余力を再確認し、本人が確認した場合だけ注文へ進む。システムは自動売買を行わない。

`HOLD` は「現在の保有を維持する」という保有状態の判断であり、価格帯・集中度・資金制約を組み合わせた結果として買い増し検討候補になることと矛盾しない。Dashboard ではこの違いを `AI 保有シグナル内訳` の直前説明と候補パネル内の注記で明示する。

## AI 補足見解の更新方針

保存済み AI 文面は手動生成のままとする。全価格帯候補への自動 LLM 実行は、利用枠、古い入力への依存、不要なノイズを増やすため導入しない。必要なときだけ最大6銘柄を更新し、7日を超えた保存済み文面は `要再確認` と表示する。ライブ候補は保存済み文面に依存せず、現在の価格帯・ポートフォリオ・保有シグナルから決定論的に算出する。

## 検証原則

本番検証は読み取り専用で行う。候補件数、順位、株数、金額、実行後構成比、`AI 保有シグナル ADD` との分離、保存済み AI 文面の鮮度表示、390px と 1280px の横スクロール不在を確認する。検証のために AI 提案レコード、取引、配当、現金、持仓データを新規作成または変更しない。

## 2026-09-23 本番確認

Railway 機能版 `62931f3` を SalesDash 正式入口へ反映し、認証付き tRPC とブラウザで読み取り専用確認を行った。`AI 保有シグナル` は HOLD 101、WATCH 5、REDUCE 7、ADD 0 のままである。一方、価格帯内は 71 銘柄（`ADD_MAIN` 21、`ADD_SMALL` 50）、既存安全ゲート通過は 64 銘柄、追加の鮮度・資料・価値・懸念条件をすべて通過した今月レビュー候補は 7 銘柄（主力 3、小幅 4）であった。

Dashboard と Buy Plans を 390px／1280px で検証し、候補7件、現在株数、追加株数、概算金額、実行後株数、実行後構成比、注文ではない旨、保存済み AI 文面の鮮度分離を確認した。両画面とも `scrollWidth <= clientWidth` で横方向のはみ出しはなかった。検証中に AI 提案生成、取引、配当、現金、持株データの書き込みは行っていない。
