## 现有金额缺失的根因

285A 当前价 ¥47,900，当前段为 ¥46,000–¥47,900.99、动作 `ADD_SMALL`；下一段为 ¥36,000–¥45,999.99、动作 `VERIFY`。285A 的四个价格带 `plannedAmount` 全部为 `null`。PYPL 的五个价格带 `plannedAmount` 也全部为 `null`。因此截图没有金额并不是前端隐藏已有数据，而是后端计划从未计算组合级可买金额。

现有 `computeAddSizing` 虽已供持仓买增建议与 WAIT 提案共用，但规则只有“现金余额 + 利息资产的 50%，再除以四段，并受单股 5% 上限约束”。以当前生产现金池 ¥95,908,963.40 计算，单段原始预算为 ¥11,988,620.43。这正是 PYPL 提案中出现约 ¥11.95m 的来源。该算法没有考虑 IBKR 1.8251x 的集中借入风险、行业现有权重，也没有区分 `ADD_SMALL` 与 `ADD_MAIN`，因此对于“打诊买い”明显过大。

## 设计约束

1. 金额必须由当前组合、现金/利息资产、IBKR 杠杆、当前与买后单股/行业权重及市场最小交易单位确定，不让 LLM 随机给数。
2. 日本股按 100 股单元向下取整；若最低单元超出风险预算，显示“今回は0株・見送り”，不可为了凑单元突破上限。
3. 已持有 symbol 必须用跨账户合计仓位，避免同一股票在两个账户时建议金额被重复放大。
4. 观察卡默认只显示“本次建议、买入价格、买后仓位”，现金、杠杆、集中度和各档分批金额放在展开层。
5. `HOLD` 与未通过理由确认的 `VERIFY` 默认建议金额为 0；`ADD_SMALL` 只用首批预算，`ADD_MAIN` 才提高分批比例。

## 设计方向

下一版不再直接使用“现金池 50% ÷ 四段”作为每个标的单次金额，而是先计算**目标总仓位**，再按价格带动作决定本次只执行其中一部分。

| 规则 | 最终口径 |
|---|---|
| 风险分母 | 使用净资产，不使用未扣借入的股票总市值 |
| 未持有目标仓位 | HIGH 1.5%、MEDIUM 1.0%、LOW 0.5% |
| 已持有目标仓位 | `ADD_SMALL` 为当前净资产比 +0.5pct；`ADD_MAIN` 为 +1.0pct；最高 5% |
| 本次分批 | `ADD_SMALL` 执行目标缺口 25%；`ADD_MAIN` 执行 50% |
| 暂停动作 | `HOLD`、`VERIFY`、`REDUCE` 的本次金额为 0；先满足价格/确认条件 |
| 流动性预算 | 现金余额 + 利息资产仅开放 25%，其余作为追证与机会缓冲 |
| IBKR 主风险 | `CAUTION` 或 1.8x 以上，本次金额减半；HIGH/CRITICAL、2.0x 以上或追证前下跌余地低于 25% 时暂停 |
| 单股上限 | 买后净资产比不超过 5% |
| 行业上限 | 买后净资产比不超过用户阈值与内部审慎线 30% 中较低者 |
| 交易单位 | 日本股 100 股、美国/新加坡 1 股、香港 1 股并提示确认实际 lot |
| 高价日股例外 | 常规首批不足 1 单元，但 1 单元仍在目标总仓位、单股/行业上限和流动性预算内时，允许建议最小 1 单元，并明确“単元調整” |

UI 默认只显示三个数字：**今回（金额与股数）／買う価格／買った後（当前实际仓位 → 买后仓位）**。点击“計算根拠を見る”后才显示剩余流动资金、IBKR 当前与买后主风险、行业权重、目标总仓位、分批比例和停止理由。285A 无真实持仓，所以必须显示 `現在 0.00%（未保有）`，不能留白，也不能伪造股数。
