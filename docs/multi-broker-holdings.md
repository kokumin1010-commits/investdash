# 同一銘柄の複数口座保有への対応

実施日: 2026-08-16

## 背景

楽天証券 iSPEED の 11 銘柄を登録しようとしたところ、moomoo に既に登録済みの
**5 銘柄が重複**していることが判明した。同じ銘柄を 2 つの証券口座で保有していた。

| 銘柄 | moomoo | 楽天 iSPEED |
|---|---|---|
| ヤクルト本社 | 400株 @3,092 | 1,800株 @2,394.50 |
| SUMCO | 700株 @1,171.56 | 1,100株 @1,137.37 |
| 住友化学 | 2,500株 @443.80 | 10,000株 @350.29 |
| オリエンタルランド | 100株 @3,709 | 200株 @3,493.20 |
| 資生堂 | 700株 @2,699.64 | 600株 @2,570.37 |

従来は保有の一意性を「ユーザー + シンボル」で判断していたため、
そのまま取り込むと **moomoo のデータが上書きされて消える**状態だった。

## 方針

合計と口座別内訳の**両方**を見られるようにした。投資判断では両方の視点が必要になる。

- **合計**: その銘柄に全体でいくら賭けているか（集中リスクの把握）
- **内訳**: どちらの口座の買いが儲かっているか（口座ごとの成績）

データは口座ごとに別レコードで保持し、表示側で合算する。

## 実装

| 層 | 変更内容 |
|---|---|
| DB | `holdings_user_symbol_broker_idx`（userId + symbol + broker）を追加。既存データは無変更 |
| DB 層 | `getHoldingBySymbolAndBroker` / `listHoldingsBySymbol` を追加 |
| 取込 | `importRouter.applyRows` の既存判定を口座込みに変更。別口座を上書きしなくなった |
| 手動追加 | `portfolio.addHolding` の重複判定を口座込みに変更 |
| ウォッチリスト昇格 | `watchlist.promote` に `broker` を追加し、口座込みで判定 |
| 集計 | `services/groupPositions.ts` を新設。シンボル単位でまとめた `GroupedPosition` を返す |
| 集中度アラート | 口座別ではなく**合計**の構成比で判定するよう変更 |
| 保有一覧 | 同一銘柄を 1 行にまとめ、合計を表示。複数口座なら内訳を展開 |
| シグナル生成 | 合計ポジション（合計株数・加重平均取得単価・合計損益率）で判定。口座別の状況も判断材料として AI に渡す |
| 一括 AI 分析 | 銘柄単位に重複排除。38 レコード → 33 件になり AI 利用枠の二重消費を回避 |
| ニュース取得 | 同上。銘柄単位に重複排除 |
| 株価取得 | シンボルで重複排除して外部 API のリクエストを削減。更新は全レコードに反映 |
| ダッシュボード | シグナル内訳・注意が必要な銘柄・構成比上位を銘柄単位（合計）に変更 |

### 合算のルール

| 項目 | 扱い |
|---|---|
| 株数 | 単純合計 |
| 取得単価 | **加重平均**（総取得額 ÷ 総株数）。単純平均では誤る |
| 評価額・取得原価 | 単純合計 |
| 現在値 | 同一銘柄なので同じ。取得できている方を採用 |
| ニュース件数 | **最大値**を採用（合計すると二重計上になる） |
| シグナル・投資カード | 銘柄単位の情報。どちらの口座にあっても拾う |
| 株価未取得 | `null` を 0 として扱わず伝播させる |

## 検証結果

### 登録

11 銘柄すべて新規登録に成功（更新 0 / スキップ 0）。
重複 5 銘柄は moomoo 側のデータが保持されたまま、楽天分が別レコードとして追加された。

### 合算値の検算

画面表示と手計算が一致することを確認した。

| 銘柄 | 合計株数 | 加重平均取得 | 評価額 | 損益率 |
|---|---|---|---|---|
| SUMCO | 1,800 | 1,150.67 | 7,056,000 | +240.67% |
| ヤクルト本社 | 2,200 | 2,521.32 | 6,340,400 | +14.31% |
| 住友化学 | 12,500 | 368.99 | 6,637,500 | +43.91% |

画面表示（SUMCO: 1,800株 / ¥1,151 / ¥7,056,000 / +240.67%）と一致。

全 5 銘柄で、合計株数と加重平均取得単価が内訳から再計算した値と一致することを確認した。

| 銘柄 | 合計 | 加重平均 | 口座別の損益率 |
|---|---|---|---|
| SUMCO | 1,800株 | 1,150.67 | 楽天 +244.65% / moomoo +234.60% |
| 住友化学 | 12,500株 | 368.99 | 楽天 +51.45% / moomoo +19.54% |
| ヤクルト本社 | 2,200株 | 2,521.32 | 楽天 +20.34% / moomoo **−6.81%** |
| 資生堂 | 1,300株 | 2,639.98 | 楽天 +38.38% / moomoo +31.76% |
| オリエンタルランド | 300株 | 3,565.13 | 楽天 −15.08% / moomoo −20.02% |

ヤクルト本社は口座によって損益が正負に分かれる。合計では +14.29% だが moomoo 分だけは含み損であり、
内訳を表示する価値がはっきり表れた事例。

### シグナル生成

SUMCO（2 口座保有）で再生成し、以下を確認した。

- 生成されたシグナルは **1 件のみ**（口座ごとに重複しない）
- 所要 17 秒、判定は WATCH（確信度 55）
- 一括分析の総件数は **33**（保有レコード 38 / 銘柄 33）と一致し、重複分析が起きない

### 画面表示

| 箇所 | 結果 |
|---|---|
| 保有銘柄の見出し | 「33 銘柄（38 口座分）」と、銘柄数と口座数の両方を表示 |
| 重複銘柄の行 | 楽天・moomoo 両方のバッジを並べ、「2 口座の合計」と明記 |
| 取得単価 | 複数口座では「加重平均」のラベルを添える |
| スマホの内訳 | 口座・損益を 1 段目、株数・取得単価・操作を 2 段目に分けて文字の重なりを回避 |
| ダッシュボード口座別カード | moomoo ¥88,961,920（27 銘柄・79.3%）/ 楽天 ¥23,158,100（11 銘柄・20.7%） |
| 集中度アラート | 合計の構成比で判定するため、口座をまたぐ集中も検知できる |

### 総資産の変化

iSPEED の 11 銘柄を追加した結果、総評価額は ¥112,120,020（+¥26,137,459 / +30.40%）となった。

## 注意点

- 複数口座の銘柄では、編集・削除は**どの口座か**を選ぶ必要がある。
  スマホでは内訳の各行に「編集 / 削除」を配置し、PC ではツールチップで口座名を示している
- AI 分析は銘柄単位。どの口座の行から実行しても同じシグナルになる
- 一括 AI 分析は銘柄単位（33 件）で走るためバッチ数は 6（1 バッチ 6 件）。
  レコード数（38）ではなく銘柄数で数えるので、口座を増やしても分析コストは増えない
