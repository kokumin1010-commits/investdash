# InvestDash 重建数据审计

## 可从仓库重建的数据

新数据库已根据 25 个 Drizzle 迁移重建。仓库中的截图核验值与恢复脚本可重建 **156 条券商持仓记录、112 个唯一标的、11 个观察标的、4 项货币基金资产、1 组 IBKR 负债与保证金信息**。所有恢复均归属于パスコード owner 用户。

2026 年 8 月的月次记录可由本次恢复后的完整 156 条持仓重新生成，因此已作为 `2026-08` 快照保存。该快照属于重建记录，不应视为旧数据库原始快照的逐字节副本。

## 无法从仓库重建的数据

`scripts/seed-july-snapshot.py` 只读取并打印已有月次快照，并不包含 2026 年 7 月的持仓明细。仓库也没有保存当月每个标的的数量、成本和价格，因此 **2026 年 7 月及更早的月次明细无法可靠恢复**。为避免伪造历史数据，本次未创建估算快照。

旧数据库内由实际运行产生、但未写入 GitHub 的新闻记录、AI 分析历史、投资咨询对话、信号历史、导入图片与部分价格带结果同样无法原样恢复。应用可在新环境中重新抓取新闻、重新分析并积累新的历史记录。

## 发布前技术验收

生产构建和 TypeScript 类型检查均通过。Vitest 共执行 **90 个测试文件、920 项测试，全部通过**，其中包括 16 项パスコード测试、月次差分、负债和保证金、持仓种子校验、行情回退、定时批次偏移与 cron 认证测试。桌面 1440 px 与手机 390 px 的仪表盘、持仓、新闻、ウォッチリスト和月次页面均已完成真实数据截图验收。

真实用户路径也已在浏览器完成验收：先用开发预览的强制锁定入口清除既有会话，再依次输入 `1`、`0`、`1`、`0` 并提交。页面成功从 InvestDash 密码门切换到“解錠済み”状态，随后加载 123 个去重标的、156 条持仓和完整资产仪表盘；该流程没有使用 devToken 绕过。

桌面端在 1440 px 视口完成可检查验收。仪表盘显示“総資産ダッシュボード”“株価データは最新です”、123 个新闻目标和完整资产分布；持仓页显示 **112 銘柄（156 口座分）**、株价最终更新时间、券商/市场/信号筛选，以及 Toyota、野村、ORCL、NVDA 等真实价格和损益。两页均在浏览器等待查询结束后读取完整 DOM 文本，而不是只依据骨架屏截图判断。

手机端使用独立无头 Chromium，以 `--window-size=390,844` 和 12 秒页面预算分别加载仪表盘与新闻页。仪表盘 DOM 包含“総資産ダッシュボード”“株価データは最新です”“123 銘柄”；新闻页 DOM 包含“ニュースモニタリング”“14 件”“未分析”。对应 390 px 全页截图也已确认卡片单列、筛选控件和底部说明没有横向溢出。

## 当前外部服务限制

模型目录仍正常提供 Gemini、GPT 和 Claude 模型，但当前项目的最小模型调用也返回账户 `usage exhausted`。因此新环境会保存真实新闻并显示 **未分析**，不会伪造情绪、摘要或投资建议；模型服务恢复后，下一次新闻任务会重试未分析记录。Data API 同样处于额度不足状态，但行情、汇率、52 周区间、sector 和 industry 已由 Yahoo 公共端点自动回退；该回退不提供 `website` 和 `businessSummary`，新增标的在 Data API 恢复前这两个字段会保持为空。
