# 顶部全市场股票搜索设计

## 问题与根因

Dashboard 顶部只有金额显示与批量更新按钮，没有直接查找股票的入口。Watchlist 新增弹窗虽然可以输入代码，但后端 `portfolio.lookup` 先调用 `normalizeSymbol`；该函数把所有非四位数字、且未带后缀的代码默认解释为美股。因此 `V03` 被查询为美国代码 `V03`，不会自动尝试新加坡的 `V03.SI`，最终显示“相場情報が見つかりません”。

## 统一搜索契约

顶部搜索与 Watchlist 新增弹窗复用同一后端搜索能力。输入可以是公司名、完整 Yahoo symbol 或裸代码。返回最多 8 个可确认候选，每项必须包含正式 symbol、显示代码、公司名、交易所／市场、币种、当前价、价格日期、证券类型，以及当前用户的 `HELD / WATCHED / UNREGISTERED` 状态。

Yahoo 公共搜索是候选发现来源；每个候选再用现有 `fetchQuote` 验证价格。候选不得仅凭字符串猜测后写入 Watchlist。搜索失败只返回空结果或清晰错误，不伪造名称、市场或价格。

## 代码与市场处理

| 输入 | 处理 |
|---|---|
| `V03` / `5DD` / `DCRU` | Yahoo 搜索优先返回 `V03.SI` / `5DD.SI` / `DCRU.SI`；单一有效结果可直接作为 Watchlist 弹窗预览 |
| `V03.SI` | 精确查询新加坡代码，不再改写 |
| `7203` | 保留既有日股规则，优先 `7203.T` |
| `AAPL` | 先验证美国裸代码；同时展示搜索发现的其他市场候选，用户自行确认 |
| `0700` / 公司名 | 由搜索结果展示香港、台湾、韩国等候选的完整 symbol、交易所与币种，不无提示自动选中 |

裸代码自动补全只发生在“找到唯一有效标的”时。若同一输入对应多个市场，顶部结果列表必须让用户点选，Watchlist 弹窗也显示候选而不是任意添加。

## 顶部交互

Dashboard 标题下方增加全宽搜索栏，桌面端与标题／批量操作形成两层布局，移动端位于标题和状态卡之间。输入后按 Enter 或搜索按钮执行，不做每次按键外部请求。结果面板显示最多 8 条，支持键盘和触控。

每个结果只提供一个主动作：

| 状态 | 动作 |
|---|---|
| 已持有 | 进入 `/holdings/:id`；多账户时进入第一个聚合标的详情并提示账户数 |
| 已观察 | 进入 `/watchlist?focus=:id` |
| 未登记 | 显示确认按钮，调用现有 `watchlist.add` 保存完整 symbol；成功后进入 Watchlist 并启动既有 AI 提案流程 |

搜索本身只读；加入 Watchlist 是明确点击后的写入，不会自动下单、不会创建持仓、不会填写目标价。

## Watchlist 弹窗兼容

现有新增弹窗继续保留。`portfolio.lookup` 改为使用相同的候选解析：`V03` 若唯一解析为 `V03.SI`，直接显示预览；歧义时返回候选并要求点选。错误提示改为覆盖日本、美国、新加坡、香港、台湾和韩国市场，不再只写“日本株／米国株”。

## 测试重点

纯函数覆盖 `V03 / 5DD / DCRU / AAPL / 7203 / 0700 / 2330.TW / 005930.KS`。后端覆盖公司名搜索、唯一 SGX 解析、歧义、不存在代码、用户隔离的持仓／观察状态。页面覆盖已持有跳转、已观察聚焦、未登记加入、重复防止、390px／1280px无横向溢出。
